CAFE KIAAN — FINAL VALIDATION REPORT
Date: 2026-09-11

1. TERMINAL ERROR FOUND AND FIXED
The Windows Odoo startup log showed a registry-load failure during cafe_kiaan_restaurant upgrade:
  psycopg2.errors.UniqueViolation: duplicate key value violates unique constraint "ir_config_parameter_key_uniq"
  DETAIL: Key (key)=(report.url) already exists.
The failing XML was data/restaurant_data.xml, where report.url was declared as a normal ir.config_parameter record. On a database where report.url already existed without that XML ID, Odoo attempted to create a duplicate key during module update.

Fix:
- Removed the duplicate-prone <record> declaration for report.url.
- Added an Odoo-native ir.config_parameter.set_param function call, which updates an existing parameter or creates it when absent.
- Kept the restaurant seed records under <data noupdate="1">.
- This makes repeated module upgrades safe and persistent.

Email logo re-fix (2026-09-12):
- Root cause found in prior attempted mail customization: it overrode a non-existent Odoo 17 mail hook (`_send_prepare_values`), so the logo transformation never ran on actual outgoing mail.
- It also used a regex that did not reliably match the absolute URL produced by Odoo's `_replace_local_links`.
- Corrected by overriding Odoo 17's actual `_prepare_outgoing_body` / `_prepare_outgoing_list` flow, replacing the local `/logo.png?company=...` reference with a CID and attaching the real company logo as an inline MIME resource.
- Added an `ir.mail_server.build_email` customization to construct the inline image as `multipart/related` around Odoo's HTML alternative, preserving ordinary attachments.
- Added a Café Kiaan sale-order creation guard so new restaurant website orders without an explicit pricelist prefer a BDT pricelist when one exists. Existing historical orders are not silently currency-converted.
- Static/CID MIME composition test passed. Live Gmail delivery was not possible in this environment.
